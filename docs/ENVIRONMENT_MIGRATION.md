# 群系、环境与玩家状态迁移

## 范围与协议

五个适配器（1.7.10、1.12.2、1.16.5、1.18.2、1.20.1）统一导出 schema 2。原有方块、方块实体、背包、位置、时间字段保持原格式；新增可选 `extras`，包含 `biomes`、`weather`、`gameRules`、`player`。schema 1 必须没有 extras，schema 2 必须包含完整 extras。所有新适配器仍能读取 schema 1；旧 JAR 会拒绝 schema 2，使用前应一起更新适配器。

群系仍限于 X/Z `[-32,32)`、Y `[0,256)`。天气和游戏规则作用于目标世界，玩家状态作用于唯一玩家。该功能不是整个存档的数据修复器，也不迁移普通实体、计划刻、进度、统计、配方解锁、任意 Forge capabilities 或模组自定义玩家持久化字段。

## 实现分层

- `Snapshot`：协议版本和完整性校验。
- `WorldExtras`：独立于 Minecraft 的群系调色板/RLE、天气、规则、保留文件及诊断。
- `BiomeCompatibility`：注册名别名、目标能力投影及未知群系后备值。
- `PlayerCompatibility`：玩家字段白名单、属性命名转换、明确的缺省属性处理和未能写入字段的恢复条件。
- 每个版本的 `EnvironmentTransfer`：原生注册表和 NBT 转换、导出、预检、应用、客户端同步。
- `Handoff` / `Epoch`：先准备环境和原有方块数据，再修改世界；群系写入后才发送完整区块包。

环境的 `prepare` 阶段解析并检查群系、规则、末影箱、药水、属性及玩家数值。已知不兼容在第一次方块修改前报错。`apply` 写入区块、规则、天气和玩家状态，然后发送能力、生命值、经验、药水、速度和时间更新。

## 群系表示与往返

共享网格为 X/Z 每方块一个样本、Y 每四方块一个样本，共 262144 个样本。索引为 `(quartY * sizeZ + z) * sizeX + x`，再经调色板和 RLE 压缩。这样既能保留旧版本一格宽的水平边界，也能保留新版本的地下群系。

现代目标的群系单元为 4×4×4，取共享网格对应单元左上角样本。旧版只有二维列群系，选取 Y=64 的样本覆盖整列。已知更名优先匹配原生目标注册表；不存在的群系显示为平原。1.18/1.20 修改时保留共享高度之外的原有群系。

每个存档的 `epoch/environment.json.gz` 保存原始网格和实际写入网格。再次导出时，当前原生样本与此前写入样本相等的格子恢复原始信息；发生变化的格子采用玩家当前修改。由此可以把新版地下群系带过旧版，再迁回新版。

限制：把原生格子改成与后备值完全相同的群系无法与“未修改”区分。旧版编辑整列、新版编辑一个四方块单元，均按目标原生粒度判定。保留文件应和存档一起备份；删除它会失去旧版无法表现的数据。

1.12 及现代版本按原生资源名匹配模组群系。1.7 缺少统一资源注册名，使用数字 ID 与类型/名称组合的内部身份；仅已识别的原版实现参与原版数字 ID 映射，不把同号模组群系当作原版。该内部身份不能替代跨模组版本的正式迁移规则。

扩展模组群系兼容时，在 `BiomeCompatibility` 增加明确的身份/别名映射，保留“先查目标注册表，再显式映射，再后备保留”的顺序；不要仅按显示名猜测。模组改变群系本身的气候或生成器行为不由本层修复。

## 天气与游戏规则

迁移下雨/雷暴开关、雨和雷暴计时器、晴天计时器及原生强度。强度读取原始字段，避免原生显示 getter 将雷暴强度乘以雨强度后丢失信息。不同版本插值和渲染仍可能略有差异。

1.7 没有晴天计时器：导入时关闭雨雷并延后对应计时器，保留文件记录晴天截止游戏刻，导出时计算剩余时长。这是旧版近似行为，不能让旧版拥有新版本的全部天气机制。

目标已有的规则按原生布尔/整数值检查后应用；目标不认识的规则保存在文件中并在之后导出。保留不等于生效，例如旧版本不认识的 `doWeatherCycle`、`doWardenSpawning` 不会改变旧版本逻辑。

## 玩家状态

本次覆盖生命、吸收生命、氧气、着火/摔落状态、移动速度向量、饥饿/饱和/消耗值、经验/等级/附魔种子、分数、游戏模式、能力、末影箱、药水效果、持久属性修饰符和主世界个人重生点。普通背包、选择槽、位置和朝向沿用原迁移路径。

玩家 NBT 使用字段白名单；目标 UUID、所在维度、背包所在路径和自定义 capabilities 不整体替换。药水使用资源名，属性使用现代资源名，修饰符 UUID 统一为两个 long，末影箱复用现有物品转换与往返检查。

不能表示的背包和末影箱物品会封存为不可使用的 `epoch:unavailable_item`，保留原始物品 NBT；拆分和移动使用当前数量与槽位，之后迁移回兼容版本时恢复。删除封存物品不会使原物品复活。无效物品数据、不支持的背包槽位，以及不能表示的药水、隐藏效果链、修改后的未知属性或游戏模式仍会阻止迁移。1.7 没有旁观模式；1.20 的无限药水时长不能降级。只有明确列出的默认属性可以在不支持它的目标省略；不把任意未知属性丢弃。

1.7 无法存储的附魔种子、旧版无法存储的重生角度随保留文件携带。恢复仅针对目标从未写入的字段；已经应用而后来消失的药水不会复活。修改重生坐标后不恢复旧角度。

导入会清除目标旧药水和持久修饰符、恢复属性基值及重生点，再读取迁入状态。装备产生的临时修饰符由原生装备逻辑维护。死亡、骑乘或睡眠中不允许导出，需先回到正常游戏状态。

## 保存、诊断与验证

保留文件使用 gzip 和临时文件原子替换。世界区块、玩家文件和该文件不构成跨文件事务；不能据此保证进程崩溃或磁盘故障时的整世界回滚。正常退出保存并备份整个存档。导入 schema 1 时清除此前的保留文件，避免混入旧迁移残留；schema 1 自身仍不携带环境状态。

运行状态的 `diagnostics.environment` 提供协议版本、群系样本数、需要保留的群系样本数、目标不生效的规则名及玩家状态应用标记。
