# 已有区块转换优化（2026-10-05）

## 原因与本次范围

此前 1.20 → 1.7 会话的诊断记录中，719 个已加载区块包含 2,736,297 个 TileEntity，原生保存队列累计等待 74,385 ms。抽查九个原生区块，33,288 个未知方块实体主要是安山岩、花岗岩、闪长岩和深板岩等普通实心地形。反复转换、逐方块实体和逐方块渲染共同放大了内存、保存和帧时间开销；这些数字是优化前的观察，并非优化后的性能结论。

本次覆盖五个版本的转换缓存、状态解析和阶段计时，并在问题最明显的 1.7 增加普通未知地形的压缩存储和区块段渲染。尚未实现完整后台转换、服务端区块段分帧写入或批量源区块预取。

## 已实现

## 1.7 普通未知地形

`epoch:packed_unknown` 是没有 TileEntity 的实心占位方块。原始状态、来源版本和来源实例保存在区块级字典中；位置使用有序数组，重复身份在字典中共享。原生区块 `Level.EpochPackedTerrain` 保存 schema 1 二进制数据；共享权威快照仍保存原始方块身份，不增加跨版本通信协议。

只有明确列入白名单、没有原始方块实体 NBT 的普通实心方块使用该路径。容器、带 NBT 方块及其他未知方块仍使用原有 TileEntity 保全方式。旧占位实体在加载时按相同条件迁移。破坏、复制和重新导出保留原始身份；删除的记录不会被重新导出。

原生保存和读取钩子独立于流式模式，`epoch.streaming=false` 时仍保留压缩数据。该功能沿用 Epoch 的单人主世界范围；渲染线程读取同一进程内发布的不可变字典，其他维度的加载不会清除主世界发布数据。

渲染按 16³ 区块段与材质合批，缓存 OpenGL 显示列表，剔除内部遮挡面及视锥外区块，并使用来源模型、纹理和动画。缓存最多 1,024 个区块，满时优先保留近处几何。每帧约 2 ms 的构建预算在区块段之间检查，**不是单个区块段的硬耗时上限**。客户端修改、资源变化及周期性光照刷新会使几何失效。

首次转换或旧数据迁移仍需要工作量；这次优化主要减少重复转换以及普通未知地形的实体数量。已经保存压缩区块后，旧版 Epoch 不认识该原生扩展；回退适配器时应同时使用更新前的存档备份，不应把旧适配器直接用于已转换的原生存档。

### 旧版打包环境修复

已改为从 `JarURLConnection` 取得真实 JAR 文件地址后计算指纹，不依赖预先挂载的 ZIP 文件系统。代码来源无法读取时只禁用原生地形缓存复用，回到正常权威转换路径，并记录一次原因；规则校验错误仍然抛出。
