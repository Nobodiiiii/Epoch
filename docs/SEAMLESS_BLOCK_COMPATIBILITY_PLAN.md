# 五版本原版方块无缝兼容：全量检查与实施方案

日期：2026-10-05。本文保留原始方案与检查基线；当前实现进度、验证和未完成项见 [实现记录](SEAMLESS_BLOCK_IMPLEMENTATION.md)。未迁移用户存档。

## 1. 结论与范围

当前问题不是几条漏掉的改名规则，而是旧版 metadata 表被当作完整跨版本语义模型使用。
这同时造成错误拒绝，以及解码成功但邻居属性、结构或 NBT 未完整转换的风险。

覆盖版本：1.7.10、1.12.2、1.16.5、1.18.2、1.20.1。目标是所有版本间共有、且目标原生机制能表达的原版方块正常使用；实际不存在的方块和不可表达的状态继续保留原始数据。
“无缝”的验收含义：身份、变种、方向、连接、结构、内容正确，往返不丢语义，切换本身不额外破坏结构或产生物品。
它不意味着把旧版游戏机制改造成新版机制；例如不同版本的树叶腐烂距离、红石规则本来就可能不同。

本轮执行：重跑 `scripts/audit_compatibility.ps1 -Offline`；五份原生注册表、25 组原生目标解码审计全部完成，共 329,190 次状态解码。
扫描了共享的 1,683 条 legacy 映射、内置规则、五版本导入导出、NBT 检查、旧版注册表枚举及相关测试。
原生审计未运行游戏 UI、未读取图片、未执行真实世界行为测试。

证据：

- `build/compatibility-rescan-20261005.log`：本轮完整执行日志。
- `build/compatibility/REPORT.md`：25 组统计矩阵。
- `build/compatibility/audit-*-to-*.json`：全部逐状态结果，不截断。
- `build/compatibility/rescan-20261005.json`：本轮按方块、失败原因、属性及值聚合的 5,076 组缺口，以及审计文件和关键源码 SHA-256。
- `.minecraft/epoch/control/1-16-5-19017a5dfd6d/status.json` 和会话快照：实际泥土 `legacy_payload`、树叶 `check_decay` 拒绝证据。

这是当前工作区的检查结果。工作区存在其他进行中的改动；本轮没有改写这些改动。原生审计成功仅表示审计执行成功，不表示被审计状态全部兼容。

## 2. 全量审计揭示的缺口

### 2.1 明确的旧版上行缺口

1.7.10 → 三个现代版本，每组拒绝 1,592 个导出条目：1,557 个 legacy payload，9 个名称不存在，24 个旧树叶属性，2 个墙属性值。
1.12.2 → 三个现代版本，每组拒绝 47 个条目：12 个头颅 legacy payload，加上相同的 9 + 24 + 2 个缺口。

| 类别 | 已确认的问题 | 处理方向 |
|---|---|---|
| 1.7 泥土 | `supportedMeta` 明确拒绝 `id=3,meta=1`；实际快照包含这个状态 | 建立 1.7 专属 dirt 0/1/2 语义；meta=1 不能因为外观相同就并为普通泥土；验证其与后来的 coarse_dirt 对应关系 |
| 六种树叶 | `check_decay`、`decayable` 仍在规范状态里 | 迁移持久性、重建目标距离与待检查状态，不能只删属性 |
| 六种全树皮原木 | `*_bark` 不是现代注册名 | 映射 `*_wood`，明确轴默认和逆向可表示范围 |
| 刷怪笼 | `mob_spawner` 不是现代方块 ID | 转为 `spawner`；同时处理方块实体类型、实体 ID 和刷怪数据 |
| 下界传送门 | `portal` 不是现代 ID | 转为 `nether_portal`，保留 axis；框架及激活行为另验 |
| 圆石墙、苔石墙 | 四向 `false/true` 与现代 `none/low/tall` 不同 | 按邻居和上方方块重建，不能把全部 true 固定变成 low |
| 头颅 | 1.12 的 12 个状态、1.7 的原始头颅状态走 legacy payload | 从 NBT 取种类、朝向及玩家资料，联合生成状态与目标 NBT |

1.7 注册表导出对每个方块枚举 meta=0..15，因此 1,557 条不能全部当作正常游戏缺陷。例如 air 的 15 个非零 metadata 也计入其中。
必须分别统计合法持久状态、世界生成/运行期可达状态、历史特殊状态与无效输入；不能简单放开全部 metadata。
本次实际出现的 dirt:1 属于必须专门覆盖的真实输入。

### 2.2 现代版本之间

1.16.5 → 1.18.2/1.20.1 没有状态解码拒绝；1.18.2 → 1.20.1 也没有。这不是 NBT 或行为已兼容的证明。

1.20.1 → 1.18.2 的 3,821 条拒绝中：3,331 条缺方块，140 条不支持含水属性，350 条不支持音符盒乐器值。
140 条中，28 条是 **不含水的 azalea_leaves / flowering_azalea_leaves**，属于现有树叶规则只列六种树木导致的明确漏项；其余 112 条是八种树叶的含水状态。
新增音色、含水状态、新增方块不能按“共同方块”直接删除差异。

现代版本仍需覆盖 sign 的 1.20 正反面文本、发光/颜色/封蜡，刷怪数据结构、容器物品及其他实体负载迁移。

### 2.3 现代返回旧版：共同方块大量误拒绝

1.20.1 → 1.12.2 共有 22,609 条拒绝，→ 1.7.10 共有 23,099 条；这包含真正新增的方块和状态。
筛选“目标导出目录存在同名条目、且输入未含 waterlogged=true”，仍有 5,145 条/88 种、4,628 条/72 种拒绝。
这个筛选只是候选集合：旧版目录含原始名称，且同名方块也可能包含新版独有状态，不能把这些数字直接当成可修复数量。

以 1.20.1 → 1.12.2 为例，明确需要进一步按语义处理的家族如下：

| 家族 | 代表缺口 | 为什么当前反查不够 |
|---|---|---|
| 楼梯 | 每种 32 个不含水转角状态被拒绝 | metadata 表只写 straight；旧版本从邻居得出转角 |
| 栅栏、玻璃板、铁栏杆 | 每种 15 个不含水连接组合被拒绝 | 表只有四向不连接模板 |
| 双箱、陷阱箱 | 各 8 个不含水左右半箱状态被拒绝 | 表只有 single；还需合并邻居关系与两个库存 |
| 门、床、双格植物 | 门 48/52 个、红床 4 个、部分植物上半部拒绝 | 信息分散在两格，不能独立按调色板转换 |
| 红石线 | 1,280 个状态拒绝 | 表只有四向 none；连接及上爬是邻居状态 |
| 栅栏门、中继器 | in_wall、locked 等拒绝 | 需要明确本地持久字段和可推导字段 |
| 草方块、菌丝、灰化土 | snowy=true 拒绝 | 积雪外观来自上方方块 |
| 藤蔓、绊线、火、紫颂植物 | 连接或附着组合拒绝 | 应从邻居推导；须区别可达状态与人工矛盾状态 |
| 音符盒 | 1,150 个状态全部拒绝 | 表只有无属性 note_block；音高原在 NBT，乐器来自环境 |
| 炼药锅 | 新版空 cauldron 拒绝，water_cauldron 缺少旧版落地通道 | 现有现代规则不进入旧版解码器 |
| 蘑菇方块/柄 | 许多表面组合拒绝 | 旧 meta 只表达有限组合，部分是真正不可表示，不能统一消除面属性 |
| 按钮、拉杆、活塞头、活板门 | 安装面、方向或运行期属性拒绝 | 逐版本区别新增安装方式、等价方向和暂态，不可套用通用忽略规则 |

### 2.4 比未知方块更容易遗漏的问题：成功不等于正确

- `LegacyStates.encode` 只按 metadata 查表，不读取邻居。表把楼梯写成 straight、栅栏写成全 false、红石线写成全 none、箱子写成 single；现代目标会接受这些模板。
- 1.12 将完整状态再压缩成 metadata 后导出；注册表目录按导出文本去重。因此上下文差异和压缩损失在审计前已经被隐藏。
- note_block 没有音高、乐器、供电属性会通过现代状态校验并使用默认值；实际有旧版 NBT 时又可能在实体工厂/负载检查阶段失败。
- 1.12 的床导出为 red_bed、旗帜导出为 white_banner，颜色在旧 NBT 中。单看状态成功不能证明颜色正确。
- 新版目标的“输入未声明属性”全部采用默认值；缺少 waterlogged 可以是合理默认，缺少 note、结构方向等则不是。
- 旧版反向映射会合并多个相同规范状态，当前没有往返唯一性证明；1.7 的反查是单个 State，1.12 是候选列表。
- 流式导入直接写 section；现有路径没有在该层统一完成结构协调与受控邻居重建。不能指望玩家以后触碰方块来补完转换。

## 3. 建议架构：以语义为中心的三阶段转换

统一五个版本的实际导入、导出、完整快照和流式区块路径：

```
源原生状态 + 源 NBT + 必要邻居/结构
  → 源版本解释器：得到完整规范语义
  → 目标投影器：状态 + NBT + 结构计划 + 更新计划
  → 目标原生构造、语义往返校验、区域原子提交
```

### 3.1 规范模型与来源

为每类方块定义：身份/材质/变种、持久属性、可推导属性、实体负载、结构关系及运行期字段。
新增带版本的规范编码标识，例如 `canonicalSchema`；独立保留实际来源版本、来源编码、原生名称/metadata、原始 SNBT/NBT。
区分“值为 false”和“尚未解析”；来源缺属性不能无条件用目标默认填充。

不要用 Snapshot.version 推测每个条目的原始来源。旧未知方块可以被多个客户端原样转发。
已带 EpochLegacyVersion 的条目按该版本解释；现存混合格式用明确格式特征及白名单迁移，歧义保留。
新格式与旧读取器协商能力；需要新字段的规范数据不得静默交给不认识它的客户端。

1.7 和 1.12 各有自己的 NativeCodec。数值 ID 只在核实原生 registry name 后使用，避免模组或异常注册环境中套错表。
Mojang BlockStateData 继续作为基础资料，但不是最终模型；后续的叶子、连接、床、花盆、头颅等修正规则必须完整补齐。
现代数据修复器可用于有明确数据版本的上行验证或指定负载；不能替代逆向转换，也不能对已经规范化的数据反复盲跑。

### 3.2 规则和程序转换器分工

保留 JSON 规则处理纯改名、有限值映射、确定的默认值迁移。
增加程序转换器处理 metadata/NBT/邻居/结构；五个版本均通过相同规划入口接入。
源规范化、目标投影和上下文重建是固定阶段，不采用无界规则递归链。
每阶段同优先级冲突继续报错；规则声明列出来源格式、目标能力、消费字段、保留字段和可逆条件。

建议接口：`normalize(native, payload, context)`、`project(canonical, target, context)`、`verifyRoundTrip(...)`。
返回结构化计划：状态、NBT、结构成员、需重建属性、待执行更新、使用规则、不能表示原因。
结果区分 EXACT、EQUIVALENT、RECONSTRUCTED、NEEDS_CONTEXT、PRESERVED；NEEDS_CONTEXT 不是立即生成未知方块。

### 3.3 上下文与缓存

调色板可以缓存纯状态转换；不能把叶距、楼梯转角、门、箱子或 NBT 转换结果只按 palette index 缓存。
上下文结果按位置和区域版本计算；相邻区块必须来自一致的权威修订，避免混用切换前后的邻居。
查询上下左右邻居，并按家族声明扩大范围：树叶需要有限半径传播；大箱、门、床等需要完整结构；红石网络不能默认局限于一个邻格。
上下文缺失时暂缓相关边界，并请求权威邻块；不能凭空生成空气当邻居。
流式加载沿用现有 load barrier，增加跨区块依赖及重试，避免在 barrier 内递归等待导致死锁；关闭依赖环需要批量准备。

## 4. 各类方块的完整处理政策

| 类别 | 规范化/落地策略 | 验收边界 |
|---|---|---|
| 普通材料、矿石、羊毛、染色块、木板、石材变种 | 名称 + 变种精确转换；每版本合法 meta 位掩码与白名单 | 同色、同材质；新增材质不替代旧材质 |
| 泥土、沙、海绵、石头 | 拆开版本语义；dirt:1 专项；普通石头/海绵不能接受后来版本的变种 meta | 验证自然生成、扩散、锄地与掉落；普通 dirt:0 不受影响 |
| 原木、全树皮木 | 材质 + 轴 + 是否全树皮；旧全树皮缺少的轴不能随意宣称等价 | 能原生表达的轴往返正确；涉及纹理方向差异先保留或证明等价 |
| 树叶 | persistent = !decayable；旧 check_decay 是检查状态，不能当距离；现代距离从树干/邻叶重算 | 导入准备期暂停腐烂，完成邻块和距离后启用；旧版按本版规则恢复检查；不会因缺邻居瞬间掉叶 |
| 杜鹃树叶 | 1.18.2 白名单补上两种不含水叶；现代支持的持久/距离照常验证 | 28 个不含水状态通过；含水仍不能降为干燥 |
| 含水属性 | 在明确不支持含水且源值为 false 的方块白名单上移除 | true 必须保留，不能把水放邻格或吞掉；double slab 等组合按合法性验证 |
| 楼梯、墙、栅栏、板、铁栏杆 | 持久方向/上下半保留，连接形状用完整邻居重建 | 目标连接算法与源有差异时按目标原生行为记录；命令制造的不可重建状态不声称等价 |
| 草地/菌丝/灰化土、藤蔓、紫颂植物 | 保留真实种类/附着位；明确可从上下文重建的字段 | 不把不存在的植物变成近似植物；无支撑情况单独测试 |
| 门、床、双格植物 | 联合读取两半；分配各版本 meta/NBT；原子提交 | 任一半缺失或不可表示则整组暂缓/保留，不能一半正常一半未知 |
| 箱子、陷阱箱 | 识别左右与朝向，分离库存槽位；旧配对规则核验 | 双箱不换槽、不复制、不合并不该配对的箱子 |
| 告示牌 | 按版本转换单面/双面、四行文本、颜色、发光、封蜡 | 只有目标支持的语义可正常落地；背面非空或不支持样式不能静默丢弃 |
| 头颅、床、旗帜 | 种类/颜色在状态与旧 NBT 间双向搬运，保留玩家资料和图案 | 1.7 没有的床色/旗帜不能替成红床或普通方块 |
| 花盆 | 旧 NBT 的植物 + data 转为 potted_*；反向重新构造 tile | 按目标可用植物白名单，空盆也覆盖；原始未知字段继续保留 |
| 音符盒 | note 在 NBT 与属性间搬运；乐器从目标支持集合与下方方块判定；供电状态明确恢复 | 所有共同音高/音色正确；新音色不能变 harp；切换不触发额外音符 |
| 刷怪笼 | 方块名、tile ID、SpawnData/SpawnPotentials、实体 ID 和数据版本联合转换 | 无可用实体转换器则保留；生成延迟和配置不重置 |
| 炉子、酿造台、漏斗、发射器、投掷器、唱片机等 | 方块实体类型、库存物品、燃烧/进度/冷却、唱片等字段专用适配 | 目标读入再导出后比较规范语义；槽位、数量、NBT 和进度不丢 |
| 炼药锅、草径、传送门 | 规范类型及水位/轴；补齐两种旧版的反向落地 | 旧版无熔岩/细雪锅时保留；完整门框与邻居行为验证 |
| 蘑菇块/柄 | 按旧 metadata 实际支持的面组合反查 | 无精确可表达组合就保留，不统一填充六面 |
| 红石线、比较器、中继器、按钮、拉杆、压力板、活板门 | 区分持久电平、连接、环境推导、待处理 tick；按版本能力转换 | 静态共同状态先支持；新版安装方式及不同机制不靠删字段兼容 |
| 活塞/移动方块 | 静止状态常规映射；运动状态需移动实体、被推动状态和 tick 联合方案 | 未完成运行态协议前只在确认稳定点切换或保留，不能当普通活塞头 |
| 水、岩浆、铁轨、火、作物 | 液位、轨道方向、年龄/燃烧和待更新状态分别处理 | 导入不额外推进时间、不复制流体、不突然触发更新链；运行态单独验收 |

所有类别都必须纳入具体的方块 ID 清单，不能对模组 `*_leaves` 等后缀套原版规则。
模组同名也不能证明语义相同；继续使用精确版本/能力约束的插件接口，缺适配则原样保留。

## 5. NBT 与更新提交

状态和 NBT 必须一起转换，允许已验证字段从 NBT 移入属性或反向移动。
验证应比较“源 → 规范语义”和“目标读回 → 规范语义”，而不是要求不同版本的 NBT 键逐字不变。
只有专用转换器声明并证明的字段可以改名/移动/转类型；其余未知字段仍须原样保留或拒绝，不放松通用损失检查。
没有实体工厂的目标方块也可能合法接收被完整消费的旧 NBT，例如音符盒和花盆；不能一律因源有 NBT 而拒绝。

提交顺序：冻结相关区域 → 收齐依赖 → 完成所有状态/NBT/结构计划 → 验证 → 批量写入 → 安装实体 → 受控重建连接/光照 → 恢复 tick → 对客户端发布。
失败在提交前中止；跨块结构必须有一致提交/恢复记录。不能用全量 neighborChanged 暴力重建，以免触发爆炸、活塞、掉落、音符或流体扩散。
优先调用无副作用的形状查询或独立确定性计算；不可避免的更新纳入显式队列与验收。
要承诺运行中的红石/流体无缝切换，还须迁移待处理方块/流体 tick 及相对延迟；当前仅有方块状态/实体的审计不能证明这一点。

## 6. 现有世界、占位方块与数据保留

不批量破坏或重写旧世界文件。导入时同时支持旧混合 SNBT 和新规范模型。
已有未知方块从 originalState/originalNbt 重新进入新规划器；满足条件的自动恢复正常方块，缺少上下文的等待，无法表达的继续保留。
已被用户破坏/替换的占位方块不能从历史数据复活；保留原有身份及删除语义。
规范数据只在成功转换和提交后升级；原始数据在验证前不被覆盖。

本方案的首要目标不依赖“正常方块旁挂一份不能表达的数据”。若未来要实现该功能，必须额外解决放置代次、活塞移动、爆炸、流体/随机刻修改、模组修改、崩溃一致性及失效，不能只按坐标和方块 ID 恢复。
已有导出已经丢掉的连接信息可在邻居完整时重建；若某次转换真正丢掉 NBT，则新规则无法凭空恢复，必须查原存档/历史快照。

## 7. 实施顺序与对应代码范围

1. **先建立可信基线。** 扩展 RegistryCatalog：保留原生 ID/meta/完整状态，不在审计前去重丢失差异；区分合法、运行期、历史、无效输入；增加源编码回读验证。输出共同可表达清单和暂不支持理由。
2. **统一规范化和五版本入口。** 扩展 CanonicalBlockState、版本 NativeCodec 和转换计划；接入两个 LegacyStates、三个 NativeStates，以及 Handoff/TerrainTransfer；清除完整快照与流式路径各自的转换差异。
3. **先交付确定映射。** 修正旧别名、dirt:1 的经验证映射、杜鹃干叶、炼药锅/土径双向迁移、合法 metadata；生成器输出最终受支持名称并保存来源依据。加入旧 originalState 回收路径。
4. **完成上下文家族。** 树叶、楼梯、连接块、积雪、双箱、门床植物；实现依赖加载、边界重算、原子结构提交及缓存隔离。这一阶段完成才把天然地形/普通建筑标为无缝。
5. **完成状态/NBT 联合家族。** 头颅、花盆、音符盒、彩色床/旗帜、告示牌、刷怪笼、容器及其内容。复用既有物品转换接口但验证其实际支持范围，不仅验证容器壳。
6. **完成运行态。** 红石、活塞、流体、火、轨道、tick 迁移和恢复；对各版本真实机制差异列出边界。不能把这部分未完成隐藏在“全部兼容”里。
7. **更新诊断和文档。** 原因区分缺身份/变种/属性、缺上下文、NBT 缺适配、结构不完整、运行态未支持、无效输入；按实际方块位置数和种类统计，另保留逐状态矩阵。

阶段间以验证结果推进，禁止以“未知方块总数下降”作为唯一验收依据。

## 8. 验收矩阵

- **状态穷举：** 五版本各自合法状态编码/解码；20 个跨版本方向 + 5 个自环。A→B→A 比较完整规范语义；三版本往返覆盖状态经过中间客户端的来源保留。
- **覆盖分母：** 对每对版本建立显式的共同可表达集合，共同集合必须 100% 正常转换；无效 meta、目标新增缺失、新机制不混入分母。每个排除项有 ID、条件、证据、测试。
- **上下文 fixture：** 六种老树木及杜鹃；树叶距边界和无树干情形；所有楼梯转角；墙高低连接；十字玻璃板/铁栏杆；双箱；全部门铰链/方向；上下半植物；积雪。
- **NBT fixture：** 16 色床/旗帜在支持版本间；带资料头颅；每类盆栽；所有共同音符/乐器；单/双面牌；刷怪配置；满库存、命名、附魔物品、炉子进度及唱片机。
- **负例：** 含水降旧版、新木种/新方块/新音色、无法表达的蘑菇面、未知 NBT、模组同后缀、异常 metadata，必须原样保留，不能变空气或近似方块。
- **边界：** 结构横跨 x/z=15/16、加载顺序互换、邻区块未载入、权威修订变化、共享高度边界。不得因缺邻居腐烂、断裂或掉落。
- **切换后编辑：** 打开门、拆楼梯、砍树、拆半箱、搬动物品、破坏/重放未知方块后再切换；不得恢复用户已删除内容。
- **运行态：** 切换前后相对 tick、红石输出、库存进度、流体量、活塞位置；不重复触发、不凭空生成物品。按目标本版机制验证，不要求不同版本红石算法完全一致。
- **持久性：** 保存重开、连续切换、异常中断/恢复；结构和原始数据一致。不同编码版本兼容协商失败必须在修改世界前报告。
- **性能：** 同一输入转换确定、幂等；纯状态缓存命中与逐位置上下文缓存隔离；依赖范围有界、无加载死锁；记录区块转换耗时和额外内存，避免整世界扫描。

最终交付应同时给出：状态结果、NBT/结构结果、实际世界行为结果。只有三者都通过的方块家族才标记为“无缝兼容”。
