## 配置与操作

Java 解析优先级为 `EPOCH_JAVA8_HOME` / `EPOCH_JAVA17_HOME`、项目的 `epoch-runtime.json`、`JAVA_HOME` / PATH / 已安装 JDK 目录。显式配置的版本不匹配时直接报告错误。可复制根目录的 `epoch-runtime.example.json`；`EPOCH_RUNTIME_CONFIG` 可指定其他配置文件。环境发现只在准备和构建入口执行。

受管理客户端堆上限由 `EPOCH_CLIENT_HEAP_MB` 配置，默认 3072 MiB。`EPOCH_WARMUP_BUDGET_MB` 默认 6144 MiB，协调器据此限制自有客户端槽位，最多四个；已成为活动版本的自有客户端仍占槽位。这是配置预算，不是实测内存占用。空闲预热默认三分钟释放。版本列表中“释放预热”会释放已准备的非活动实例。

手动修改兼容规则后运行 `python scripts/epoch_control.py reloadrules`。重载失败保留先前已发布规则。`-Depoch.fixedView=true` 是显式长期固定视图策略，默认关闭。

全部关联实例退出后，可运行 `python scripts/compact_world.py <authority目录>`。默认每次最多检查/清理 500 个文件、标记 100 个索引文件并使用十秒软时间预算；未完成时再次运行会续接进度。世界版本或保留引用改变时重新标记。活动读者、未完成提交和恢复日志都会阻止回收，正常游玩不会持续扫描权威仓库。

## 兼容与核对边界

所有适配器和启动组件必须一起更新到流式协议 5。原有区块对象和世界绑定继续使用 schema 3，玩家/环境快照继续使用 schema 2；新增的检查点侧车使用 schema 5。旧 schema 3/4 检查点缺少完整的原始地形边界，无法证明其玩家状态与当前地形一致，因此拒绝将其混合恢复；需要一致的完整备份或明确的数据迁移决定，不能静默补造历史边界。

安装后的代码身份由清单发布。开发目录、缺少清单或安装元数据改变时禁用原生投影复用，仍从权威内容转换。外部修改不可变对象应通过显式完整性检查发现，不恢复“每次查询重新哈希”的策略。

初始命名空间只在首次进入世界前建立。它固定原生区域中已有的位置，并将完整原生区块的首次激活版本保存为不可变对象；未完成生成的记录和新生成的区块不能充当原始版本。离线回收始终保留这些初始对象。尚未接纳的原始区块需要原始存档及其原生版本读取器；来源缺失时拒绝生成替代地形。已经绑定权威数据的世界不能通过关闭流式模式绕过保存边界，也不能直接用另一版本打开原始原生目录。

本次核对使用当前生产源码、五版适配器和注册表工具的编译结果、主机与原生组件编译、脚本语法检查。构建命令使用 `assemble compileAuditJava --offline`，不执行测试任务。编译日志位于 `build/audit-build/`。未进行游戏运行、桌面或浏览器自动化，也未读取图片作为视觉输入；本记录不提供未经测量的性能收益或运行验收结论。
